# Founder Intelligence: инструкция для проверки из GitHub

Эта инструкция нужна проверяющему, который клонирует репозиторий `https://github.com/Akana92/Founder_Intelligence`, создает свой локальный `.env`, запускает Docker и проходит путь от PDF до отчета. Секреты владельца проекта в репозиторий не кладутся.

## 1. Клонирование и окружение

```powershell
git clone https://github.com/Akana92/Founder_Intelligence
cd Founder_Intelligence
Copy-Item .env.docker.example .env
```

Откройте `.env` локально и заполните только свои значения. В репозиторий эти строки должны попадать только пустыми, как в `.env.docker.example`:

```env
OPENAI_API_KEY=
OPENAI_STARTUP_API_KEY=
LANGSMITH_API_KEY=
```

`OPENAI_API_KEY` и `OPENAI_STARTUP_API_KEY` нужны для live LLM и онлайн-ресерча. `LANGSMITH_API_KEY` нужен только если вы хотите увидеть трассы в LangSmith. В tracked `.env.docker.example` эти поля должны оставаться пустыми.

## 2. Запуск в Docker

Запустить продукт без админки:

```powershell
docker compose up --build
```

Запустить продукт вместе с Admin Console:

```powershell
docker compose --profile admin up --build
```

Откройте:

- Founder Workspace: `http://127.0.0.1:3000/`
- API docs: `http://127.0.0.1:8000/docs`
- Admin Console: `http://127.0.0.1:8501/`

Обычная остановка:

```powershell
docker compose down
```

Не используйте `docker compose down -v` для обычной остановки: эта команда удалит именованный volume с кейсами и отчетами.

## 3. Live, offline и кеш

По умолчанию `.env.docker.example` задает `FOUNDER_CASE_FIXTURE_MODE=live`. Это означает реальный workflow: после явного согласия пользователя онлайн-ресерч может использовать OpenAI и web-search capability.

Для проверки без затрат API задайте в `.env`:

```env
FOUNDER_CASE_FIXTURE_MODE=deterministic_offline
```

Офлайн-демо не обращается к интернету. Оно нужно для защиты от сетевых сбоёв и для демонстрации интерфейса.

Если онлайн-ресерч уже был выполнен для того же case/revision/snapshot, система должна использовать кеш. Не нажимайте повторный запуск ресерча без необходимости: новый live-запуск может потратить OpenAI API токены.

## 4. Основной путь владельца: от PDF до отчета

1. Откройте `http://127.0.0.1:3000/`.
2. Нажмите `Новый анализ`.
3. Нажмите `Выбрать файлы`, выберите PDF с описанием стартапа и нажмите `Загрузить проект`. Когда список материалов готов, нажмите `Запустить анализ выбранных материалов`.
4. Дождитесь экрана профиля `Вот как я понял ваш стартап`.
5. Проверьте поля `Продукт`, `Клиент`, `Проблема`, `Монетизация`, `Стадия`.
6. Если всё приемлемо, нажмите `Подтвердить и продолжить`. Это владелец проходит `Gate 2`.
7. Откройте или оставьте правую панель `Copilot`. Она показывает один следующий вопрос или действие, которое сильнее всего разблокирует анализ.
8. Когда Copilot задает вопрос, выберите источник:
   - `Ответ`: ввести ответ вручную;
   - `Документ`: добавить или использовать документ;
   - `Публичный поиск`: открыть выбор между реальным онлайн-поиском и локальной демонстрацией;
   - `Не знаю`: оставить gap открытым.
9. Для поиска выберите `Публичный поиск`, затем режим `Онлайн-ресерч` или `Офлайн-демо`. Для онлайн-поиска поставьте галочку `Разрешаю онлайн-ресерч` и нажмите `Запустить онлайн-ресерч`. Для no-cost проверки выберите офлайн-режим, подтвердите отдельное согласие и нажмите `Запустить офлайн-демо`.
10. После завершения откройте `Метрики`, `Рынок`, `Риски`, `План действий`.
11. В `План действий` нажмите `Принять рекомендацию`, если рекомендации подходят. Если хотите поменять вводные, нажмите `Изменить допущения`. Это решение владельца для `Gate 3`.
12. После принятия рекомендации перейдите в `Отчёты`.
13. Если отчет еще не создан, нажмите `Сформировать отчёт`. Это финальная фиксация `Gate 4`.
14. После фиксации должны быть доступны `PDF`, `HTML` и `JSON`. Для PDF нажмите `Открыть PDF` в центре отчета.

## 5. Что делают кнопки Copilot

`Ответ` сохраняет ввод пользователя как `founder_statement`. Это рабочее заявление основателя, а не автоматически подтвержденный факт.

`Документ` нужен для приватных доказательств: выручка, MRR, cash, burn, клиенты, договоры, счета, банковские остатки.

`Онлайн-ресерч` ищет только публичные ориентиры: конкуренты, цены, рыночные аналоги, каналы, regulatory context, похожие модели. Он не должен отправлять приватный документ или ответы основателя в публичный поиск.

`Офлайн-демо` использует локальные fixtures без интернета. Оно должно быть явно подписано как offline/demo.

`Не знаю` оставляет вопрос в списке gaps. Анализ может продолжиться, но выводы будут слабее.

## 6. Provenance и границы данных

Система обязана разделять происхождение данных:

- `source_fact`: найдено в загруженном документе;
- `founder_statement`: ответ пользователя;
- `public_benchmark`: внешний публичный ориентир;
- `ai_scenario`: сценарная оценка LLM или расчетной модели.

`founder_statement`, `public_benchmark` и `ai_scenario` не становятся `source_fact` автоматически. Публичный research не заполняет частную выручку, MRR, cash, burn, клиентов, договоры, счета или банк.

## 7. Case ID, Admin и LangSmith

В левом сайдбаре Founder Workspace показывается текущий проект и короткий `caseId`. Полный `caseId` также может быть в URL: `http://127.0.0.1:3000/?caseId=...`.

Чтобы открыть тот же кейс в Admin Console, нажмите `Открыть в Admin` или перейдите на `http://127.0.0.1:8501/` и выберите тот же case ID в списке.

LangSmith показывает трассы только если:

- в `.env` есть `LANGSMITH_API_KEY`;
- включен `DDA_LANGSMITH_TRACING=true`;
- был выполнен live workflow, а не только чтение кеша.

Трейсинг санитизирован: в LangSmith не должны попадать текст документов, локальные пути, имена файлов, prompt, PII или секреты.

## 8. Troubleshooting

Если `Запустить онлайн-ресерч` неактивна, проверьте, что открыта вкладка `Публичный поиск`, выбран режим `Онлайн-ресерч`, поставлена галочка `Разрешаю онлайн-ресерч` и сейчас не выполняется другое действие. Кнопка также остаётся недоступной, пока backend не предложил research-action для текущего кейса.

Если кнопка активна, но запуск завершился ошибкой, проверьте `OPENAI_API_KEY`, `OPENAI_STARTUP_API_KEY`, доступность API и сообщение об ошибке. Для проверки интерфейса без ключей используйте `Офлайн-демо`.

Если ресерч сразу завершается без новых токенов, проверьте, не используется ли кеш того же case/revision/snapshot. Это нормальное поведение для повторного просмотра.

Если Admin показывает другой кейс, сравните `caseId` в Founder Workspace и выбранный case ID в Admin Console.

Если PDF не появляется, проверьте, что вы прошли `Gate 2` кнопкой `Подтвердить и продолжить`, приняли рекомендацию в `План действий` кнопкой `Принять рекомендацию`, а затем нажали `Сформировать отчёт` в разделе `Отчёты`.

Если LangSmith пустой, проверьте `LANGSMITH_API_KEY`, `DDA_LANGSMITH_TRACING=true`, выбранный проект LangSmith и то, что запуск был live, а не offline/cache.

Если порты заняты, измените host-порты в `.env`: `WEB_PORT`, `API_PORT`, `ADMIN_PORT`. Внутри Docker Compose сервисы продолжают общаться по внутренним портам.

## 9. Что должно попасть в GitHub

В GitHub попадают исходники, Dockerfile, `compose.yaml`, тесты, fixtures без секретов и документация. В GitHub не попадают `.env`, загруженные документы, runtime databases, LangSmith/API traces, `.next` build output, acceptance cache и локальные диагностические папки.

## 10. Быстрая проверка перед публикацией

Из корня репозитория выполните:

```powershell
git ls-files .env
git check-ignore .env
docker compose config --quiet
python -m pytest tests/smoke/test_github_release_readiness.py tests/smoke/test_docker_packaging.py -q
npm --prefix frontend/founder run typecheck
npm --prefix frontend/founder run lint
```

Ожидаемый результат:

- `git ls-files .env` ничего не выводит — локальный файл с ключами не отслеживается;
- `git check-ignore .env` выводит `.env` — Git действительно его игнорирует;
- Compose config, smoke-тесты, typecheck и lint завершаются без ошибок.

Перед `git push` дополнительно просмотрите `git status --short`: там не должно быть `.env`, загруженных PDF, runtime-баз, trace-файлов, `.next` или acceptance-кэшей.
